# XIAO 地磁気の座標系キメラ問題（AG=NWU / MAG=NED 混在）根本原因解析

- 作成日: 2026/09/04
- 対象: SeedESP32-ICM20948（XIAO + ICM-20948 / AK09916 内蔵地磁気）→ pypilot（`boatimu.py` 側・本リポジトリ外）
- 状態: **解析結果・確定方針の記録のみ。コード修正は本ドキュメントでは実施しない。**
- 関連: `AXIS_CALIBRATION.md`（2026/09/02 までの軸マッピング確定の記録）

---

## エグゼクティブサマリ（結論）

これまでのすべての事象（ジャイロの逆キック、深ピッチでの逸脱、これまでのロール不安定）のパズルは、
**XIAO から送られているデータが「加速度・ジャイロ」と「地磁気」で異なる座標系
（右手系と左手系、すなわち NWU と NED）が混ざった『キメラ状態』になっていること**で
一貫して説明できる。

`boatimu.py` 側での一時しのぎ（モグラ叩き）はここで終了とする。
根本原因は XIAO ファームウェア側の地磁気座標系の不整合であり、
**地磁気の Y と Z を「両方」反転して加速度・ジャイロと同じ NWU（Z-up 右手系）に完全同期させる**ことで解決する。

## パズルのピース（発生していた不具合）

1. ジャイロの逆キック
2. 深ピッチでの逸脱
3. これまでのロール不安定

---

## 1. なぜすべての不具合が起きていたのか（完全な特定）

XIAO のファームウェア（`ICM-20948_WE`）の特性と、現在の設定
`AG_NED_SIGN = { 1, 1, 1 }` / `MAG_NED_SIGN = { 1, 1, 1 }` がすべての元凶である。

### 1-1. 加速度・ジャイロ（AG）の真実

現在の `{ 1, 1, 1 }` は、基板の印字通りの **NWU（X=北 / Y=西 / Z=上）** を出力している。

### 1-2. 地磁気（MAG）の真実

ICM-20948 に内蔵されている地磁気センサ（AK09916）は、物理的に加速度センサに対して
**Y 軸と Z 軸が反転して実装**されている。
つまりライブラリから `{ 1, 1, 1 }` で生データをそのまま取り出すと、
地磁気だけが **NED（X=北 / Y=東 / Z=下）** になって出力される。

### 1-3. これが引き起こしていた 3 つの悲劇

**① ジャイロの逆キック**
ジャイロは NWU なので「左回り（CCW）がプラス」、地磁気は NED なので「右回り（CW）がプラス」を出力していた。
カルマンフィルタの中で「右に回った！」「いや左だ！」と 2 つのセンサが殴り合っていたため、
回した瞬間に逆キックが発生していた。

**② ティルト補償の崩壊**
フィルタは加速度（Z=上 / Y=西）を基準に地磁気を補正しようとする。
しかし地磁気は（Z=下 / Y=東）を向いているため、外積（3D の掛け算）が破綻する。

**③ これまでの解析で「Y 反転」が効いた理由**
`Y 反転 (1, -1, 1)` を試してロールが直ったのは、Y 軸が揃ったからである。
しかし Z 軸が逆のまま（左手系）なので、コンパスの回転方向が逆転してしまった。

---

## 2. 究極の解決策（XIAO 側での完全同期）

正解は `boatimu.py` で **Y を反転させることでも、Z を反転させることでもない**。
XIAO のファームウェアで、**地磁気の Y と Z の「両方」を反転させ、
加速度・ジャイロと完全に同じ NWU（Z-up 右手系）に揃えること**である。

これにより、ジャイロの逆キックも、すべてのティルト（ピッチ・ロール）の逸脱も一瞬で消滅する。

### アクション① XIAO ファームウェアの修正と書き込み

`src/main.cpp` の軸マッピングを以下のように変更し、XIAO にフラッシュする。

```cpp
// 修正前
static const int8_t MAG_NED_SIGN[3] = { 1, 1, 1 };

// 修正後（地磁気を加速度・ジャイロと同じ NWU に完全同期）
static const int8_t MAG_NED_SIGN[3] = { 1, -1, -1 };
```

※ 同時に、`boatimu.py` に追加した `SERIAL_MAG_CAL` などの行列や、`gz = -gz` などの
一時コードはすべて削除（または無効化）し、pypilot をピュアな標準状態に戻す。

### アクション② 設置場所でのフル 3D 再キャリブレーション（必須）

軸の符号（Y と Z）を反転させたため、これまでのキャリブレーションのオフセット値
（ハードアイアン）はすべて使い物にならなくなる。

1. XIAO をフラッシュし、pypilot を再起動する
2. すぐに `Lock Compass Calibration` を外す
3. 現地（ラズパイ近傍）で、上下逆さまや斜めを含む**完全な 8 の字キャリブレーション**を行う
4. 新しいオフセットをロックする
